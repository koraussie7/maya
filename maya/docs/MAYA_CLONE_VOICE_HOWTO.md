# 클론 목소리를 쓰는 방법 — 실행 가능한 경로 정리 (2026-11-24)

**결론**: 클론 품질은 **VoxCPM2**, 응답 속도는 **piper(0.15~0.34초)**.
둘은 같은 파이프라인에서 **경로를 나눠** 쓸 수 있다. 아래 3가지 방법이 실제로 가능하고,
4번(piper 파인튜닝)은 전제조건이 우리 환경과 맞지 않는다.

---

## 방법 1 — 클론 전용 모드 (품질 최우선, 지연 큼)

```bash
MAYA_PERSONA=lyra_vex_b      # personas/lyra_vex_b.yaml → clip_ref_speaker_b.wav
TTS_ENGINE=voxcpm-api
VOXCPM_API_URL=https://openbmb-voxcpm-demo.hf.space
MAYA_TTS_PREWARM=1           # 콜드스타트 선소비(8~15s)
```

| 항목 | 실측                                |
| ---- | ----------------------------------- |
| 음색 | F0 192Hz → 클론 192Hz (기준 유지)   |
| 발음 | 전사 CER 0                          |
| 지연 | 첫 문장 10~24초 (Space 대기열 변동) |
| 캐시 | 동일 문장 재요청 0초                |

**실측 근거**: `maya/docs/MAYA_PERSONA_VOICE.md`, `voxcpm_tts_bench.json`

**쓸 때**: 프로필 음성, 인사말 사전 생성, 오프라인 배치.

---

## 방법 2 — 하이브리드 (권장) ⭐

고정 응답·짧은 문장은 **미리 클론으로 합성해 캐시**하고, 실시간 응답은 piper로 넘긴다.

```bash
TTS_ENGINE=piper             # 실시간 기본 (0.15~0.34s)
MAYA_TTS_CLONE_PREWARM=1     # 라우트 응답을 클론 음성으로 미리 생성
```

동작:

1. 서버 기동 시 `routes.yaml`의 `say` 문장들을 **클론으로 1회 합성** → 디스크 캐시
2. "그만", "응", "고마워", "다시 말해줘" → **클론 음성 즉시 재생**(0초)
3. 자유 대화 → piper (0.2초) 또는 VoxCPM(설정 시)

| 구간             | 음성     | 지연    |
| ---------------- | -------- | ------- |
| 라우트 고정 응답 | **클론** | 0초     |
| 짧은 대화        | piper    | 0.2초   |
| 긴 대화(옵션)    | 클론     | 10~24초 |

**현재 코드로 1단계는 이미 가능**: 예열이 `"안녕하세요."`를 합성해 캐시에 저장한다
(`tts 캐시 hit: 안녕하세요!` 로그 확인). 여기에 라우트 문장을 추가하면 된다.

---

## 방법 3 — 우리 음성으로 piper 학습 (근본 해결)

piper는 **과거에 화자별 파인튜닝을 공식 지원**했다(`piper(train)`, espeak-ng 음소변환 전제).
현재 저장소는 **추론 전용**이라, 학습하려면 별도 파이프라인이 필요하다.

### 전제조건과 우리 상황

| 전제조건                        | 우리 상황                                                        |
| ------------------------------- | ---------------------------------------------------------------- |
| espeak-ng 한국어 G2P            | ✅ 가능(`espeak-ng -v ko`)                                       |
| 학습 데이터(단일 화자, 1~3시간) | ⚠️ **B 화자 단독 발화는 21분 녹음 중 일부**(79~113구간)          |
| torch 2.x                       | ⚠️ 이 venv는 Intel Mac torch 2.2.2 (VITS 학습은 가능하지만 느림) |
| GPU                             | ❌ **110 서버 GPU 없음** → CPU 학습                              |

**판단**: 지금 데이터(단일 화자 20~30분)로는 **VITS 파인튜닝 품질이 불충분**할 가능성이 높다.
2~3시간 단일 화자 녹음이 확보되면 재검토.

---

## 방법 4 — 하지 말아야 할 것

| 시도                           | 이유                                                     |
| ------------------------------ | -------------------------------------------------------- |
| VoxCPM을 110 CPU 서버에서 상주 | RTF가 Space보다 나쁠 수 있음(CPU)                        |
| 클론/piper를 문장마다 섞기     | **같은 대화에서 목소리가 바뀐다** — 사용자가 즉시 알아챔 |
| 폴백(say) 결과 캐시            | 이미 수정 — 폴백은 캐시하지 않는다                       |

---

## 즉시 실행 체크리스트

1. `maya/personas/*.yaml` → `voice.ref_wav` + `voice.prompt_text` 확인
2. 클론 음성 품질 확인: `integration/voxcpm_speak.py --voice b`
3. 하이브리드 전환: `TTS_ENGINE=piper` + 라우트 문장 사전 합성
4. (선택) 긴 응답만 클론: `MAYA_TTS_LONG_CLONE=1` + `MAYA_TTS_LONG_CHARS=60`
