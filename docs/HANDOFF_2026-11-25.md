## 2. 프론트엔드 `/decisions` — 배포 전 반드시 수정

파일: `maya-ui/app/src/routes/decisions/+page.svelte` (아래 §2.5 에 전문).

### 2.1 문제 1 — API 불일치 (치명, 페이지 동작 안 함)

현재 코드:

```js
const mod = await import('$lib/mayaClient');
client = new mod.MayaClient({ url: mod.resolveWsUrl() });
client.on('state', (s) => ...);       // ❌ 존재하지 않는 메서드
client.on('error', (e) => ...);       // ❌
client.on('decision', (d) => ...);    // ❌
client.connect();
```

실제 `maya-ui/app/src/lib/mayaClient.js:42`:

```js
constructor(hooks = {}) { this.hooks = hooks; ... }
// hooks: onPhase / onError / onDecision
```

그리고 `resolveWsUrl()` 은 **`$lib/mayaClient` 가 아니라 `$lib/config`** 에 있다 (`config.js:43`).

→ `new MayaClient({ url })` 는 hooks 객체에 `url` 키만 넣는 셈이라 **콜백이 하나도 등록되지 않는다**.
`client.on(...)` 은 `TypeError: client.on is not a function` 으로 즉시 throw.

**수정안 (그대로 적용 가능)**

```svelte
<script>
  import { onMount, onDestroy } from 'svelte';
  import { base } from '$app/paths';
  import { MayaClient } from '$lib/mayaClient';

  let rows = [];
  let phase = 'idle';
  let lastError = null;
  let cleared = false;

  function toRow(d) { /* 기존 toRow 유지 — all_scores 는 §2.2 처리 */ }

  const client = new MayaClient({
    onPhase: (p) => (phase = p),
    onError: (code, msg) => (lastError = `${code}: ${msg}`),
    onDecision: (d) => {
      rows = [toRow(d), ...rows].slice(0, 200);
      cleared = false;
    },
  });

  onMount(() => client.connect());   // url 은 config.js 가 결정
  onDestroy(() => client.close());
</script>
```

### 2.2 문제 2 — `all_scores` 는 객체가 아니라 배열

```js
const top = Object.entries(all).sort(...)   // ❌
```

`all` 은 `[{ route_id, score, source }]` 이므로:

```js
function toRow(d) {
  const all = Array.isArray(d.all_scores) ? d.all_scores : [];
  const top = all
    .map((c) => [c.route_id, Number(c.score ?? c.prob ?? 0)])
    .sort((a, b) => b[1] - a[1])
    .slice(0, 3);
  // ... 나머지 동일
}
```

### 2.3 문제 3 — `ts` 단위 / each key

`ts` 는 epoch ms(number). `new Date(iso)` 는 동작하지만 number 검증을 넣는 편이 안전:

```js
const d = typeof ts === 'number' ? new Date(ts) : new Date(String(ts));
```

`{#each rows as r (r.ts + r.text)}` 는 **숫자 + 문자열 = 문자열 연결**이 우연히 동작하지만,
`ts` 가 모두 `undefined` 로 정규화되면 key 충돌. `(r.ts + '|' + r.text)` 로 명시할 것.

### 2.4 없는 필드

`laya_used`, `laya_source`, `elapsed_ms` 는 `mayaClient.js` 의 `decision.log` 핸들러(L130~146)가
**전달하지 않는다**. 현재 페이지가 참조 → 항상 `false` / `null`.
배지의 `(below threshold)` 힌트를 살리려면 `mayaClient.js` 페이로드에 `laya_source` 를 추가(3줄).

또한 연결 표시는 `connection === 'open'` 이 **절대 참이 되지 않는다** — `session.state` 는
`idle | connecting | listening | thinking | speaking | yielded | held | ended | error` 를 준다.
`<span class:on={phase === 'listening' || phase === 'speaking'}>` 또는 `phase !== 'idle'` 로.

# File: maya-ui/app/src/routes/decisions/+page.svelte
<script>
  /**
   * /decisions 페이지
   *
   * 백엔드의 `decision.log` 서버 메시지를 구독해서
   * Laya reranker PoC 결과를 시각화한다.
   *
   * 한 줄 항목 예:
   *   {
   *     text, route_id, source, score, threshold,
   *     abstained, rule_hit, laya_hit, all_scores, ts
   *   }
   */
  import { onMount, onDestroy } from 'svelte';
  import { base } from '$app/paths';

  /** @type {import('$lib/mayaClient').MayaClient | null} */
  let client = null;
  /** @type {Array<any>} */
  let rows = [];
  /** @type {string | null} */
  let connection = null;
  /** @type {string | null} */
  let lastError = null;
  /** @type {boolean} */
  let cleared = false;

  /** 결정 로그 한 건을 화면용 row로 정규화 */
  function toRow(d) {
    const all = d.all_scores || {};
    const top = Object.entries(all).sort((a, b) => b[1] - a[1]).slice(0, 3);
    return {
      ts: d.ts || new Date().toISOString(),
      text: d.text || '',
      route_id: d.route_id || '(abstain)',
      source: d.source || (d.abstained ? 'abstain' : '-'),
      score: typeof d.score === 'number' ? d.score : null,
      threshold: typeof d.threshold === 'number' ? d.threshold : null,
      abstained: !!d.abstained,
      rule_hit: !!d.rule_hit,
      laya_hit: !!d.laya_hit,
      laya_used: !!d.laya_used,
      laya_source: d.laya_source || null,
      elapsed_ms: typeof d.elapsed_ms === 'number' ? d.elapsed_ms : null,
      top,
    };
  }

  onMount(async () => {
    const mod = await import('$lib/mayaClient');
    client = new mod.MayaClient({ url: mod.resolveWsUrl() });
    client.on('state', (s) => (connection = s));
    client.on('error', (e) => (lastError = String(e)));
    client.on('decision', (d) => {
      rows = [toRow(d), ...rows].slice(0, 200);
      cleared = false;
    });
    client.connect();
  });

  onDestroy(() => {
    if (client) client.close();
  });

  function clear() {
    rows = [];
    cleared = true;
  }

  function sourceBadge(s) {
    if (s === 'rule') return 'rule';
    if (s === 'laya') return 'laya';
    if (s === 'abstain') return 'abstain';
    return 'muted';
  }

  function fmtTs(iso) {
    try {
      const d = new Date(iso);
      return d.toLocaleTimeString('ko-KR', { hour12: false });
    } catch {
      return iso;
    }
  }

  function fmtProb(p) {
    if (p == null) return '—';
    return (p * 100).toFixed(1) + '%';
  }
</script>

## 5. 이번 세션에서 확정된 설계 결정

1. **decision.log 는 서버 → 클라이언트 단방향 브로드캐스트** — 클라이언트는 수신만. 저장/집계는 UI 메모리(최대 200행).
2. **abstain 은 별도 메시지가 아니라 같은 `decision.log` 타입의 `abstained:true`** — 페이지가 행 배경색으로 구분.
3. **Laya 는 옵트인** (`MAYA_LAYA=1`) — 기본 경로(rule) 회귀 없음. mock 이 기본 허용.
4. **rule 이 항상 우선** — `match_with_laya` 는 룰 히트 시 Laya 를 호출하지 않고 `source:"rule"`.
5. **FireRedVAD 는 1차 컷 전용** — `use_turn_detector=False` 로 배치 벤치에서 NAMO 2차 컷을 끊다.
6. **로컬 LLM 은 대화 경로에서 사용하지 않는다** — 규칙 경로(`turn_decision.py`)가 정본. AirLLM 은 실험/오프라인 전용.
7. **`config.py` / `llm.py` / `tts.py` / `session.py` 의 시스템 경로는 변경하지 않는다** — 보수적 설정 유지.

## 6. 알려진 함정 (재발 방지)

| 함정 | 내용 |
| --- | --- |
| 클라이언트 API | `MayaClient` 는 hooks 만 받는다. `client.on(...)` 은 없다. `resolveWsUrl` 은 `$lib/config` 소속 |
| 상태 표시 | `session.state` 는 `phase` 값을 준다 → `connection === 'open'` 은 **절대 참이 되지 않는다** |
| each key | `r.ts` 가 `undefined` 면 `(r.ts + r.text)` 키가 겹친다 → `'\|'` 구분자 사용 |
| 벤치 실시간 | `bench_vad_firstcut.py` 는 `--fast` 없이 실행해야 턴 개수가 라이브와 일치 (sleep 없으면 무음 900ms 미도달 → 턴 0개) |
| 커밋 순서 | 본체(untracked)보다 테스트를 먼저 커밋하면 CI import 실패 |
| AirLLM 스트리밍 | 현재 DELTA 는 `generate()` 1회 결과를 쪼갠 **가짜** 스트리밍 — 체감 지연 개선 없음 |
| 테스트 모듈 복원 | `test_llm_airllm.py` 의 `_restore_modules` 가 가짜 모듈을 무조건 pop → 실행 순서에 따라 누수 가능 (현재 5건은 독립이라 통과) |
