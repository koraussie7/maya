# floorcall (yashraz23/floorcall) — Maya 음성 파이프라인 적용 평가

> 사용자 링크: <https://github.com/yashraz23/floorcall>
> 평가일: 2026-11-25
> 평가자: AI 에이전트
> 결론: **직접 이식 대상 아님.** 다만 "**환각 방지 검증 루프(생성 → 결과 확인 → 재시도)**"라는 패턴이 Maya의
> `etri_gate_ko_probe.py` 가 지적한 문제(규칙 기반 의도 판정의 한계)와 정확히 같은 자리에 꽂힌다.
> 코드가 아니라 **아이디어 하나**를 가져온다.

---

## 1. 무엇인가

`floorcall` 은 이름 그대로 **"floor(현장/층)" + "call"** 로, 하드웨어(또는 현장 장비)에서 발생한
호출/이벤트를 받아 **에이전트가 처리하고, 처리 결과가 실제로 반영됐는지 확인(verify)한 뒤에만 완료로
표시**하는 데모 저장소다. 핵심 구조는 다음 세 단계다.

```
① call (이벤트/요청 수신)
      ↓
② act  (에이전트가 도구 호출로 처리)
      ↓
③ verify (결과를 다시 조회해 실제 반영 확인)  ── 실패 시 ②로 재시도
```

라우선서(LuGE)·Rocket.Chat·Moonshine 같은 저장소와 달리 **서비스·SDK·모델을 배포하지 않는다**.
학습용/데모용 예제 모음에 가깝고, 우리가 앞서 검토한 저장소들보다 코드 표면이 훨씬 작다.

| 항목                      | 값                                                            |
| ------------------------- | ------------------------------------------------------------- |
| 저장소                    | [yashraz23/floorcall](https://github.com/yashraz23/floorcall) |
| 성격                      | 데모/예제 (라이브러리 아님)                                   |
| 음성 AI (STT/TTS/VAD/LLM) | ❌ 없음                                                       |
| WebRTC / 실시간 오디오    | ❌ 없음                                                       |
| 우리가 가져올 것          | **act → verify → retry 루프 패턴**                            |

> 즉 이 저장소는 "음성"과는 무관하다. Maya에 붙일 수 있는 것은 **에이전트 실행 신뢰성** 부분이다.

## 2. 왜 Maya에 의미가 있는가 (우리 실측과 연결)

### 2.1 방금 측정한 결과 — 규칙 게이트는 이미 한계에 부딪혔다

`integration/etri_gate_ko_probe.py` 실측 (2026-11-25):

```
오판: etri 원본 9/15, 한국어 규칙(동사목록만 추가) 0/15
turn_detector(NAMO): 잡담 6건 중 '턴 종료' 판정 0건
```

| 판정기                                        | 오판                 | 의미                             |
| --------------------------------------------- | -------------------- | -------------------------------- |
| etri 원본 게이트 (영어 정규식 `[a-zA-Z']+`)   | **9/15**             | 한국어 토큰 0개 → 명령 전부 거부 |
| 한국어 동사목록 규칙 (`열어`, `켜`, `줄여` …) | **0/15**             | 이 15문장에서는 완벽             |
| NAMO turn_detector                            | 잡담 6건 중 종료 0건 | 백채널을 끊지 않음 (좋음)        |

**0/15는 성과가 아니라 경고다.** 문장 15개를 규칙 목록에 딱 맞게 골랐기 때문이다. 규칙 게이트는
(a) 목록에 없는 동사("봐줘", "알아봐", "정리해" …)를 거부하고 (b) 규칙을 넓히면 잡담을 명령으로
오인한다. 이 트레이드오프는 문장 수를 늘리면 반드시 드러난다.

### 2.2 floorcall 패턴이 대체하는 것

규칙으로 **미리 판정**하지 않고, **실행한 뒤 확인**한다.

| 단계             | 규칙 게이트 (현재)         | floorcall 방식                                         |
| ---------------- | -------------------------- | ------------------------------------------------------ |
| "이게 명령인가?" | 동사 목록 매칭 → 오판 위험 | **판정하지 않는다** — 일단 실행                        |
| 실행             | —                          | 도구 호출 (창 열기, 볼륨 조절 …)                       |
| 성공 판단        | 무조건 성공 리턴           | 앱 상태/프로세스/볼륨을 **다시 읽어** 확인             |
| 실패 시          | 조용히 무시                | 다른 도구로 재시도 → 그래도 실패면 "못 했어" 라고 말함 |

Maya에서 `그만`/`확인` 같은 짧은 발화는 규칙에 의존하지 않고 **도구 결과로 판정**하는 편이 정확하다.
`etri_gate_ko_probe.py` 의 `KO_VERBS` 목록은 이 관점에서 **임시 안전장치**로 격하된다.

## 3. Maya 적용 설계 (최소 변경)

### 3.1 기존 구조

```
/ws → session.py (턴 루프)
        ├─ STT (faster-whisper / Qwen3-ASR)
        ├─ LLM (keirouter :20128, smartrouter-9)
        └─ tools (라우트: "그만", "응" …) → TTS
```

현재 도구 호출 후 **성공 여부를 확인하지 않는다**. 응답 텍스트만 TTS로 넘긴다.

### 3.2 verify 루프 삽입 지점

```python
# maya-ui/backend/app/tools/executor.py (신규, ~80줄)
async def call_with_verify(tool, args, verify_fn, retries=2):
    """도구 실행 → 실제 반영 확인 → 실패 시 재시도."""
    last = None
    for attempt in range(retries + 1):
        result = await tool(**args)
        if await verify_fn(args, result):          # ② 실행 후 상태 재조회
            return {"ok": True, "result": result, "attempts": attempt + 1}
        last = result
        await asyncio.sleep(0.2 * (attempt + 1))   # UI 반영 지연 흡수
    return {"ok": False, "result": last, "attempts": retries + 1}
```

각 도구에 **검증 함수**를 짝지어 등록한다.

| 도구                 | 검증 함수 (실제 반영 확인)                                       |
| -------------------- | ---------------------------------------------------------------- |
| `open_app("유튜브")` | `pgrep -f "YouTube"` / `osascript` 로 최전면 앱 이름 조회        |
| `set_volume(30)`     | `osascript -e 'output volume of (get volume settings)'` == 30 ±2 |
| `open_url(url)`      | Chrome/Safari 활성 탭 URL 조회                                   |
| `play_music`         | 미디어 상태 조회 (`now playing` 계열)                            |
| `capture_screen`     | 저장 파일 존재 + mtime 이 현재 시각 근처                         |

핵심: **검증은 "명령을 보냈다"가 아니라 "시스템 상태가 바뀌었다"를 본다.** 이게 floorcall의 전부다.

### 3.3 응답 문구도 검증 결과를 따르게

```python
if not outcome["ok"]:
    reply = f"{tool.label} 못 했어. 다시 말해줄래?"   # 거짓 완료 보고 금지
```

지금은 도구 호출이 실패해도 LLM이 "열었어요"라고 말할 수 있다. 이 한 줄이 그걸 막는다.

## 4. 평가

### 4.1 긍정

1. **"성공했다"는 말의 신뢰도가 올라간다** — 음성 비서에서 가장 치명적인 실패는 "못 했는데 했다고 말하는 것".
2. **규칙 게이트 의존을 줄인다** — `KO_VERBS` 0/15 라는 취약한 기반을 도구 검증으로 대체 가능.
3. **코드가 작다** — 80줄 내외. 되돌리기 쉽다.
4. **NAM0/NAMO 회귀 없음** — 턴 판정 계층을 건드리지 않고 **도구 실행 계층**만 바꾼다.

### 4.2 부정 / 리스크

1. **지연 증가** — 도구마다 확인 조회가 한 번 더 붙는다(예: `osascript` 왕복 30~80ms).
   짧은 응답에서 첫 TTS 지연이 그만큼 늘어난다 → **백그라운드 확인 + 낙관적 응답** 옵션 필요.
2. **검증 불가능한 도구가 있다** — "메모 작성" 같은 부수효과는 상태 조회가 애매하다. 검증 있는 도구만 대상.
3. **재시도 폭주** — 실패가 반복되면 앱 중복 실행. 도구별 멱등성 확인 필요(`open` 은 멱등이 아님).
4. **음성과 무관** — WebRTC/FireRedVAD 로드맵(`docs/MAYA_WEBRTC_FIREREDVAD_ROADMAP.md`)에는 기여 없음.
5. **저장소 성숙도** — 데모 수준. 우리 코드베이스로 옮길 때 의존성(AI SDK 등)은 버리고 패턴만 가져와야 한다.

### 4.3 폐기 조건

- 도구 검증으로 첫 응답 지연이 **+150ms 초과** → 백그라운드 검증으로 되돌리거나 폐기.
- 재시도로 인한 **중복 실행 1건이라도 발생** → `open` 계열 도구는 verify 제외.
